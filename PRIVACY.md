# Private-data boundary

No account credentials, real Fact contents, personal numeric Fact identifiers, transcripts, original databases, private Core state, real Bee receipts, private absolute paths or embedded original packages are distributed. Tests and fixtures are fictional. All new operation data from the supported single_bridge.py entry must remain in an owner/SYSTEM-only Windows folder outside repositories and this package tree. No repository writes occur in the runtime path.

Consent binds the supplied ID, four selected fields, one read, local capture, display and one fresh-process recovery. This is not consent to conversations, additional Facts, source writes, publication or background reads. The pinned Bee CLI itself may read its existing user authentication files and access Bee during a separately authorized live acquisition. Its internal behavior and logging are not independently audited by this package. No Bee installation, login, logout or settings change occurs here.

Success retains selected Fact text/ID, source metadata, capture/transport/consent receipts, the recovery seal and answer in that private operation folder. The terminal displays the selected answer and its ID/provenance only following successful recovery. Do not record/share that terminal or operation folder unless separately authorized. The bridge does not accept private text via command-line arguments; a user-supplied Fact ID remains visible in local process command lines during the CLI read.

Caught failure or interruption removes selected capture, receipt, seal, recovered answer and completion artifacts from the new operation; it keeps only a private attempt (ID/consent metadata) and sanitized FAILED receipt. No retries run. Cleanup refusal yields `CLEANUP_UNVERIFIED`, never a success claim. Do not rerun against the same operation or treat a pending store as complete. A second reader cannot consume a completed/claimed store.

An OS crash, forced process kill, disk failure or permission interference can prevent cleanup and leave protected private remnants. Automatic deletion is not guaranteed; deletion is not secure erasure, and no filesystem backup/monitoring/administrator isolation is claimed. A native process is created suspended, assigned to a non-breakaway kill-on-close Windows Job and then resumed. An uncatchable parent crash in the brief creation-to-assignment interval can leave a **suspended, not-yet-executing** orphan. This is a known Windows process-launch limitation; no Bee execution has begun in that interval. Detected containment failure refuses execution.

On success, manually remove only the selected random operation folder after you no longer need it. The application intentionally has no broad recursive cleanup command. Retained consent/attempt metadata also contains the chosen ID; keep it private. A COMPLETE receipt is meaningful only with its entire valid contract, the matching recovered view, distinct PIDs and unchanged bound evidence hashes; a partial file or pending state is not success evidence.

This public derivative replaces the inherited private historical refusal-policy fingerprint with the fingerprint of a fictional test Fact. It does not publish that private identifier or its fingerprint. The public fictional value exercises the refusal mechanism; it is **test policy metadata**, not real Bee evidence or the private package's historical-target policy. This is an intentional policy difference from the preserved private packages, which retain their earlier records and seals. Source publication does not authorize a read of anyone's records; an operator must use their own separately authorized account and Fact.

Path/audit checks protect the intended capability boundaries of trusted local source. They are not a sandbox against hostile code, same-user tampering, concurrent filesystem races or administrators. The fresh reader denies sockets, subprocesses, registry, database and outside-file access through its audit hook; only the validated operation and package/interpreter files are permitted. The acquisition parent intentionally permits the one native CLI process for a live operation. No private workspace or database is opened by the bridge.

The retained H5 pair CLI is only for fictional regression interfaces in disposable copies. It can read operator-supplied external files and write inside real/ using its historical controls; never provide private captures to it. The new private-root/consent/Job guarantees apply to single_bridge.py. Use a trusted native CLI installation and parent directories not writable by other principals; executable pinning is not an atomic file-lock against concurrent replacement.
